## 1. Кратко

Mobile-first веб-приложение. Пользователь описывает бизнес и идею поста, выбирает соцсеть (Telegram, Instagram, YouTube). ИИ (Gemini 3.5 Flash-Lite) за несколько секунд пишет **несколько готовых вариантов поста**. В каждом есть заголовок, текст, призыв к действию (CTA) и хэштеги. Текст появляется на экране постепенно, по мере генерации. Любой вариант можно перегенерировать, а любой пост из истории — скопировать одним нажатием.

## 2. Проблема

Владельцу малого бизнеса или SMM-специалисту нужно регулярно писать посты под разные площадки. Сейчас это делается так:
- текст пишется с нуля или через универсальный чат-бот, которому каждый раз заново объясняют, что за бизнес и какие правила у площадки;
- ответ чат-бота приходится вручную разбирать на заголовок, текст и хэштеги, а потом подгонять под лимиты площадки;
- удачные посты теряются в переписке.

## 3. Цели и не-цели

**Цели MVP**
1. Путь от описания до скопированного поста — **меньше 60 секунд** на телефоне.
2. Посты с первого раза учитывают формат площадки: длину, структуру, число хэштегов.
3. Варианты заметно отличаются друг от друга: подходом, а не только перестановкой слов.
4. Удачные посты не теряются: история на устройстве, копирование в одно касание.

**Не-цели MVP**
- Публикация в соцсети напрямую (через API Telegram, Meta, YouTube).
- Генерация картинок и видео.
- Аккаунты, вход, синхронизация между устройствами.
- Оплата и подписки.
- Контент-план и календарь публикаций.

## 4. Пользователи

| Персона | Контекст | Что важно |
|---|---|---|
| **Владелец малого бизнеса** (салон, кофейня, магазин) | Пишет посты сам, с телефона, между делами | Быстро, просто, «под ключ» |
| **SMM-специалист / фрилансер** | Ведёт несколько клиентов | Варианты на выбор, разные площадки, история |
| **Эксперт / блогер** | Telegram-канал, YouTube | Свой тон, заголовки для YouTube |

Основной язык интерфейса — русский. Посты пишутся на русском, узбекском (латиница) или английском (см. FR-3).

## 5. Пользовательские сценарии

1. **Первый пост.** Открываю сайт → описываю бизнес («студия лазерной эпиляции в Ташкенте…») → пишу идею («акция −20% в ноябре») → выбираю Instagram → «Сгенерировать» → вижу, как заполняются 3 варианта → копирую понравившийся → вставляю в Instagram.
2. **Не понравилось.** Нажимаю «Ещё раз» на одном варианте — перегенерируется только он. Или «Обновить все» — перегенерируются все три.
3. **Тот же бизнес, другая площадка.** Описание бизнеса уже подставлено с прошлого раза. Меняю только идею и соцсеть.
4. **Вернуться к старому посту.** Открываю «Историю» → нахожу пост → «Копировать» → вставляю.

## 7. Правила площадок

Правила передаются в промпт и проверяются на клиенте. Лимиты нужно перепроверить перед релизом: площадки их меняют.

### 7.1. Telegram (пост в канале)
- Лимит текста — 4096 символов. Подпись под фото или видео — 1024 символа, поэтому целимся в **≤1000** символов, чтобы пост можно было опубликовать с картинкой.
- Заголовок — первая строка поста, при копировании выделяется **жирным**.
- Короткие абзацы, допустимы списки и эмодзи-маркеры.
- Хэштегов 0–3, в конце поста.
- CTA — подписаться, написать в личку, перейти по ссылке.

### 7.2. Instagram (подпись к посту или Reels)
- Лимит подписи — 2200 символов, целимся в **≤1500**.
- Видны только первые ~125 символов до «ещё», поэтому заголовок-хук стоит в начале.
- Хэштегов **3–5**. Instagram ограничивает их число — актуальный лимит проверить перед релизом.
- Ссылки в подписи не кликабельны: CTA вида «ссылка в профиле», «пишите в Direct».

### 7.3. YouTube (видео)
- Заголовок — **≤100** символов, ключевые слова в начале.
- Описание — до 5000 символов, целимся в **≤1500**. Первые 2–3 строки видны без раскрытия.
- Хэштегов 3–5. Первые три показываются над заголовком, если их больше 60, YouTube игнорирует все.
- CTA — подписаться, лайк, комментарий, ссылка в описании.

### 7.4. Формат копирования поста целиком

```
Telegram:   **{заголовок}**\n\n{текст}\n\n{cta}\n\n{#хэштеги через пробел}
Instagram:  {заголовок}\n\n{текст}\n\n{cta}\n.\n.\n{#хэштеги}
YouTube:    Заголовок: {заголовок}\n\nОписание:\n{текст}\n\n{cta}\n\n{#хэштеги}
```

Markdown-разметка `**…**` при вставке в Telegram превращается в жирный текст. Для Instagram используется только чистый текст.

## 8. ИИ: модель и промптинг

### 8.1. Модель

- **Gemini 3.5 Flash-Lite**, ID `gemini-3.5-flash-lite`. Стабильная версия, выпуск — июль 2026. Самая быстрая и дешёвая модель линейки 3.5.
- Google относит её к **предыдущему поколению**: модель поддерживается для продакшена, но новые модели уже есть. ID модели вынесен в переменную окружения `GEMINI_MODEL`, чтобы сменить модель без правки кода.
- `thinking_level: "minimal"` — значение по умолчанию. Для коротких текстов рассуждения не нужны, а они удлиняют ответ и стоят как выходные токены.
- `temperature`, `top_p` и `top_k` для Gemini 3.x **устарели** и игнорируются, в будущих моделях будут давать ошибку. Не передаём. `candidate_count` не поддерживается, поэтому несколько вариантов получаем отдельными запросами (FR-12).
- **Structured output**: ответ строго по JSON-схеме (§8.2).
- **Стриминг**: `streamGenerateContent?alt=sse`. В карточке модели стриминг явно не указан — проверить в первом спайке (§13, риск R1).

### 8.2. Схема ответа (один вариант)

```json
{
  "type": "object",
  "properties": {
    "title":    { "type": "string", "description": "Заголовок / хук" },
    "body":     { "type": "string", "description": "Основной текст поста" },
    "cta":      { "type": "string", "description": "Призыв к действию, 1–2 предложения" },
    "hashtags": { "type": "array", "items": { "type": "string" }, "description": "Без пробелов, с #" }
  },
  "required": ["title", "body", "cta", "hashtags"],
  "propertyOrdering": ["title", "body", "cta", "hashtags"]
}
```

Порядок полей задан явно: при стриминге поля приходят в той же последовательности, в какой показываются на экране.

### 8.3. Разнообразие вариантов

Параметра temperature нет, поэтому разнообразие задаётся промптом. Каждый из 3 параллельных запросов получает свой **угол подачи**:

| № | Угол | Суть |
|---|---|---|
| 1 | **Выгода** | Что клиент получит, конкретика, цифры |
| 2 | **История** | Ситуация клиента, сторителлинг, эмоция |
| 3 | **Вовлечение** | Вопрос, интрига, провокация к комментарию |

При перегенерации варианта («Ещё раз») в промпт передаётся предыдущий текст с указанием «сделай заметно иначе».

### 8.4. Структура промпта

- **System instruction** (одинаковая для всех запросов): роль — опытный SMM-копирайтер; правила площадки из §7; язык поста; запрет выдумывать факты, цены и контакты, которых нет в описании бизнеса; вместо них — плейсхолдеры `[цена]`, `[адрес]`.
- **User message**: описание бизнеса, идея, тон, угол подачи, быстрая правка (если есть).
- Пользовательский ввод передаётся внутри разделителей `<business>…</business>` и `<idea>…</idea>`. Инструкции внутри них не выполняются: это защита от prompt injection.

### 8.5. Стоимость

Цены Gemini Developer API, стандартный тариф, на ноябрь 2026: вход **$0.30**, выход **$2.50** за 1 млн токенов.

Оценка на одну генерацию из 3 вариантов: вход ≈ 3 × 900 токенов, выход ≈ 3 × 450 токенов.
- Вход: 2700 × $0.30 / 1 млн ≈ $0.0008
- Выход: 1350 × $2.50 / 1 млн ≈ $0.0034
- **Итого ≈ $0.004** (около 50 сум) за генерацию, **≈ $4 за 1000 генераций**

Для разработки и демо подходит **бесплатный тариф**. Его лимиты смотреть в Google AI Studio. Данные бесплатного тарифа Google может использовать для улучшения своих продуктов — это нужно указать в политике конфиденциальности.

## 9. UX и экраны

### 9.1. Принципы mobile-first
- Базовая ширина — **360 px**, далее 390/430 px. На десктопе — центральная колонка шириной ≤640 px.
- Главные действия («Сгенерировать», «Копировать») — внизу, в зоне большого пальца. Нижняя панель закреплена, учитывает `safe-area-inset-bottom`.
- Цели касания — не меньше **44×44 px**. Шрифт полей — не меньше 16 px, чтобы iOS не зумил страницу при фокусе.
- Без ховер-зависимостей, без горизонтального скролла страницы.
- Светлая и тёмная темы — по системной настройке.
- Работает на слабой сети: интерфейс грузится быстро, текст начинает появляться без ожидания полного ответа.

## 10. Архитектура

### 10.1. Стек

Стек сохраняет текущий каркас репозитория.
- **Фронтенд**: статические файлы в `public/`, ванильный JS + CSS, без сборки. Компонентов мало, фреймворк не нужен. Если интерфейс разрастётся — переход на Preact/Vite (решение после MVP).
- **Бэкенд**: Vercel Function `api/generate.js` (Node 20+).
- **Gemini**: прямые REST-запросы через `fetch` к `generativelanguage.googleapis.com`, без SDK. Это ноль зависимостей и полный контроль над SSE.
- **Хранение истории**: `localStorage` (≤200 постов ≈ 0,5 МБ). Если упрёмся в лимит — IndexedDB.
- **Секреты**: `GEMINI_API_KEY` и `GEMINI_MODEL` — переменные окружения Vercel, на клиент не попадают.

### 10.2. Поток данных

```
Браузер ──POST /api/generate (SSE)──▶ Vercel Function ──streamGenerateContent──▶ Gemini
   ▲            × 3 параллельно             │  валидация, лимиты, промпт
   └──────── события: delta / done / error ─┘
```

### 10.3. API

`POST /api/generate` — генерирует **один** вариант (клиент делает 3 параллельных запроса).

Запрос:
```json
{
  "business": "строка, 20–1500",
  "idea": "строка, 5–1000",
  "platform": "telegram | instagram | youtube",
  "language": "ru | uz | en",
  "tone": "auto | friendly | expert | selling | neutral",
  "angle": "benefit | story | engagement",
  "tweak": "shorter | longer | more_emoji | no_emoji | new_cta | null",
  "previous": { "title": "", "body": "", "cta": "", "hashtags": [] }
}
```

Ответ — `text/event-stream`:
```
event: delta   data: {"text":"<кусок JSON от модели>"}
event: done    data: {"post":{...}, "usage":{"in":912,"out":431}}
event: error   data: {"code":"rate_limited","retryAfter":20}
```

Клиент склеивает куски `delta` и разбирает **неполный JSON** небольшим толерантным парсером, чтобы показывать поля по мере заполнения. По `done` сервер отдаёт итоговый проверенный пост.

Коды ошибок: `invalid_input` (400), `rate_limited` (429), `upstream_error` (502), `blocked_content` (422 — ответ остановлен фильтрами безопасности), `timeout` (504).

### 10.4. Модель данных истории

```ts
type HistoryItem = {
  id: string;            // crypto.randomUUID()
  createdAt: string;     // ISO
  platform: 'telegram' | 'instagram' | 'youtube';
  language: 'ru' | 'uz' | 'en';
  idea: string;
  angle: 'benefit' | 'story' | 'engagement';
  post: { title: string; body: string; cta: string; hashtags: string[] };
  starred: boolean;
};
// localStorage: "spg.history.v1" → HistoryItem[]
//               "spg.prefs.v1"   → { business, platform, language, tone }
```

## 11. Нефункциональные требования

| Область | Требование |
|---|---|
| Скорость | Первый символ на экране — **≤2 с** (p50) после нажатия. Полный вариант — **≤8 с** (p90). Первая загрузка страницы на 4G — ≤1,5 с, JS+CSS ≤50 КБ gzip. |
| Надёжность | Таймаут запроса к Gemini — 30 с. При 429/503 от Gemini — 1 автоповтор с паузой. Ошибка одного варианта не влияет на другие. |
| Защита от злоупотреблений | Сайт публичный, а ключ API платный. Нужны: лимит **10 генераций в минуту и 100 в сутки на IP**, проверка длины ввода на сервере, проверка `Origin`. В MVP лимит хранится в памяти функции (грубо). До публичного запуска — Upstash Redis или Vercel KV. Плюс лимит бюджета в Google Cloud. |
| Безопасность | Ключ только на сервере. Ввод пользователя изолирован в промпте (§8.4). Вывод модели вставляется через `textContent`, никакого `innerHTML`. |
| Приватность | Описания и посты на сервере **не хранятся**. В логах — только метаданные: время, площадка, токены, код ошибки. История живёт только на устройстве. Нужна страница политики конфиденциальности: данные передаются в Google Gemini API. |
| Доступность | Контраст по WCAG AA, подписи у полей, `aria-live="polite"` для появляющегося текста, работа с клавиатуры, учёт `prefers-reduced-motion` (без мигающего курсора). |
| Поддержка | iOS Safari 16+, Android Chrome последних 2 версий, десктоп Chrome/Safari/Firefox. |

## 12. Метрики

Без сторонней аналитики в MVP: события пишутся в логи функции, на клиенте — анонимные счётчики (если позже подключим Vercel Analytics).

| Метрика | Цель |
|---|---|
| Генерации, завершившиеся копированием хотя бы одного варианта | ≥ 60 % |
| Доля перегенераций на одну генерацию | наблюдаем: высокая доля — сигнал, что промпт слабый |
| Ошибки генерации | ≤ 2 % |
| Время до первого символа (p50) | ≤ 2 с |
| Средняя стоимость одной генерации | ≤ $0.006 |

## 13. Риски

| ID | Риск | Что делаем |
|---|---|---|
| R1 | Стриминг вместе со structured output работает не так, как ожидается (поля приходят не по порядку, JSON рвётся) | Спайк в первый день. План Б — текстовый формат с маркерами `### TITLE` / `### BODY`, разбор на клиенте. |
| R2 | Модель предыдущего поколения, со временем её выведут из эксплуатации | ID в `GEMINI_MODEL`, промпты не завязаны на конкретную модель |
| R3 | Публичный эндпоинт сожжёт бюджет | Лимиты по IP, лимит бюджета в Google Cloud, оповещение о расходах |
| R4 | Низкое качество узбекского текста | Проверить на 10–20 реальных брифах до включения языка. При плохом результате — пометка «бета». |
| R5 | ИИ выдумывает цены, адреса, гарантии | Запрет в system prompt + плейсхолдеры `[цена]`. Подсказка в интерфейсе «Проверьте факты перед публикацией». |
| R6 | Лимиты площадок (особенно хэштеги Instagram) изменятся | Правила вынесены в один конфиг `platforms.js` |
| R7 | Оплата Google Cloud из Узбекистана | Проверить привязку карты Visa/Mastercard узбекского банка до перехода с бесплатного тарифа |

## 15. Критерии приёмки MVP

- [ ] На iPhone (Safari) и Android (Chrome) шириной 360–430 px весь путь проходится одной рукой, без горизонтального скролла.
- [ ] После «Сгенерировать» за ≤2 с начинает появляться текст, приходят 3 разных варианта с 4 полями каждый.
- [ ] Посты соответствуют лимитам из §7 или явно помечены как превышающие.
- [ ] «Ещё раз» меняет только свой вариант, «Обновить все» — все три.
- [ ] «Копировать» кладёт в буфер пост в формате §7.4. Вставка в Telegram даёт жирный заголовок.
- [ ] После перезагрузки страницы история на месте, копирование из списка работает в одно касание.
- [ ] Ключ Gemini не виден в коде страницы и сетевых запросах браузера.
- [ ] 11-й запрос за минуту с одного IP получает понятное сообщение о лимите.
- [ ] Ошибка Gemini в одном варианте показывает «Повторить» и не ломает другие.

## 16. Открытые вопросы

1. **«Постепенный ввод текста»** понят как постепенное появление сгенерированного текста (стриминг). Если имелся в виду пошаговый ввод данных (мастер: шаг 1 — бизнес, шаг 2 — идея, шаг 3 — соцсеть), нужно уточнить: это меняет экран «Создать».
2. Нужен ли узбекский язык в MVP или достаточно русского?
3. Нужен ли один профиль бизнеса или сразу несколько (для SMM-специалиста с клиентами)?
4. Кто пользователи на старте: только вы (тогда можно закрыть сайт паролем и отложить лимиты) или публичный доступ?
5. Название и бренд: пока рабочее «Social Posts Generator».
6. Нужен ли формат YouTube Shorts (короткое описание) отдельно от обычного видео?
