## 2. Архитектура

```
┌──────────── Браузер (public/) ────────────┐        ┌──── Vercel Function ────┐        ┌── Gemini API ──┐
│ form → 3 × streamGenerate() ──POST, SSE──────────▶ │ api/generate.js          │──SSE──▶│ streamGenerate │
│ card ← partial-json ← delta  ◀────────────────────── │ validate → limit →      │◀──────│ Content        │
│ store (localStorage)                       │        │ prompt → gemini → post  │        └────────────────┘
└────────────────────────────────────────────┘        └─────────────────────────┘
```

- Без сборки и без зависимостей в рантайме. Фронтенд — ES-модули из `public/js/`, бэкенд — Node 20+.
- Код, общий для клиента и сервера (правила площадок, валидация, хэштеги), лежит в `public/js/core/`. Функции импортируют его относительным путём, Vercel включает эти файлы в бандл функции автоматически.
- Один HTTP-запрос — один вариант поста. Три варианта — три параллельных запроса (FR-12).

## 4. API

### 4.1. `GET /api/health`

`200 {"ok": true, "mode": "live" | "mock", "model": "gemini-3.5-flash-lite"}`. Ключ не раскрывается. Используется для плашки «Демо-режим» в интерфейсе.

### 4.2. `POST /api/generate`

**Заголовки запроса:** `Content-Type: application/json`, `Accept: text/event-stream`. Тело — не больше 16 КБ.

```json
{
  "business": "Студия лазерной эпиляции в Ташкенте…",
  "idea": "Акция −20% в ноябре",
  "platform": "instagram",
  "language": "ru",
  "tone": "auto",
  "angle": "benefit",
  "tweak": null,
  "previous": null
}
```

**Валидация** (`core/validate.js`, одинаковая на клиенте и сервере):

| Поле | Правило |
|---|---|
| `business` | строка; после `trim` 20–1500 символов (`countChars`) |
| `idea` | строка; после `trim` 5–1000 |
| `platform` | ключ `PLATFORMS` |
| `language` | ключ `LANGUAGES` |
| `tone` | ключ `TONES` |
| `angle` | из `ANGLES` |
| `tweak` | `null` или ключ `TWEAKS` |
| `previous` | `null` или объект `{title, body, cta, hashtags[]}`: строки ≤ 5000, хэштегов ≤ 30. Обязателен, если `tweak` не `null`. |

Перед проверкой из строк удаляются управляющие символы, кроме `\n` и `\t`, а `\r\n` заменяется на `\n`. Лишние поля игнорируются.

**Порядок обработки:**
1. Метод не `POST` → `405`.
2. `Origin` не разрешён (§3.1) → `403 {"code":"forbidden"}`.
3. Тело не JSON, больше 16 КБ или не прошло валидацию → `400 {"code":"invalid_input","field":"business","message":"…"}`.
4. Превышен лимит → `429 {"code":"rate_limited","retryAfter":<сек>}` и заголовок `Retry-After`.
5. Иначе — `200` с заголовками `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`, затем `res.flushHeaders()` и события.

Шаги 1–4 отвечают обычным JSON: стрим ещё не начат.

**События SSE** (`_lib/sse.js` пишет `event: <имя>\ndata: <json>\n\n`):

| Событие | Данные | Когда |
|---|---|---|
| `start` | `{"requestId":"r_…"}` | Сразу после заголовков |
| `delta` | `{"text":"…"}` | Каждый текстовый кусок ответа модели (кусок сырого JSON) |
| `done` | `{"post":{title,body,cta,hashtags},"warnings":[…],"usage":{"in":912,"out":431,"thoughts":0}}` | Модель закончила, итоговый JSON разобран и нормализован |
| `error` | `{"code":"…","message":"…","retryAfter":20?}` | Ошибка после начала стрима. Это всегда последнее событие. |

Каждые 15 с без данных отправляется комментарий `: ping\n\n`, чтобы прокси не закрыли соединение.

Если клиент закрыл соединение (`req.on('close')`), запрос к Gemini прерывается через `AbortController`. Это попадает в лог как `aborted`.

**Коды ошибок**

| `code` | Где | Причина |
|---|---|---|
| `invalid_input` | 400 | Валидация |
| `forbidden` | 403 | Чужой `Origin` |
| `rate_limited` | 429 / `error` | Наш лимит по IP или 429 от Gemini после повтора |
| `blocked_content` | `error` | `promptFeedback.blockReason` или `finishReason` ∈ `SAFETY`, `PROHIBITED_CONTENT`, `BLOCKLIST`, `SPII` |
| `truncated` | `error` | `finishReason = MAX_TOKENS` и JSON не разобрался |
| `bad_output` | `error` | Модель вернула невалидный JSON или пустые обязательные поля |
| `timeout` | `error` | Нет ответа от Gemini за `GEMINI_TIMEOUT_MS` |
| `upstream_error` | `error` | Прочие ошибки Gemini (4xx/5xx), сеть |
| `not_configured` | `error` | `live`-режим без ключа (только если mock принудительно выключен) |

Сообщения `message` — на русском, пригодные для показа пользователю (§9.6).

### 4.3. Лимиты (`_lib/ratelimit.js`)

- Ключ — IP из первого значения `x-forwarded-for`, иначе `req.socket.remoteAddress`.
- Два скользящих окна: 60 с и 24 ч. Хранится `Map<ip, number[]>` с метками времени, старые метки отбрасываются при каждой проверке. Записей не больше 10 000: при переполнении удаляются самые старые IP.
- Запрос засчитывается до вызова Gemini. Запросы, отклонённые на шагах 1–3, не засчитываются.
- `retryAfter` = секунды до освобождения самой старой метки в превышенном окне.
- **Ограничение:** у каждого экземпляра функции своя память, поэтому лимит приблизительный. До широкого публичного запуска — перенос в Upstash Redis (v0.2). Вторая линия защиты — лимит бюджета в Google Cloud (PRD R3).

## 5. Интеграция с Gemini (`_lib/gemini.js`)

### 5.1. Запрос

```
POST https://generativelanguage.googleapis.com/v1beta/models/${GEMINI_MODEL}:streamGenerateContent?alt=sse
x-goog-api-key: ${GEMINI_API_KEY}
Content-Type: application/json
```

```json
{
  "systemInstruction": { "parts": [{ "text": "<§6.1>" }] },
  "contents": [{ "role": "user", "parts": [{ "text": "<§6.2>" }] }],
  "generationConfig": {
    "responseMimeType": "application/json",
    "responseJsonSchema": {
      "type": "object",
      "properties": {
        "title":    { "type": "string" },
        "body":     { "type": "string" },
        "cta":      { "type": "string" },
        "hashtags": { "type": "array", "items": { "type": "string" }, "maxItems": 10 }
      },
      "required": ["title", "body", "cta", "hashtags"]
    },
    "maxOutputTokens": 2048,
    "thinkingConfig": { "thinkingLevel": "minimal" }
  }
}
```

- `temperature`, `topP`, `topK` и `candidateCount` **не передаются** (PRD §8.1).
- Ключ передаётся только в заголовке, никогда в URL. URL и тело запроса не логируются.
- Порядок ключей в схеме = порядок полей в ответе. Проверяется в спайке (R1). Если модель не соблюдает порядок, переключаемся на `responseSchema` с `propertyOrdering: ["title","body","cta","hashtags"]` — это флаг `SCHEMA_FLAVOR` в `gemini.js`.

### 5.2. Разбор стрима Gemini

Ответ — SSE со строками `data: {…}`. Из каждого куска:
- `candidates[0].content.parts[]` — берём `text` у частей **без** `thought: true` и отдаём клиенту как `delta`;
- `candidates[0].finishReason` — запоминаем последний;
- `usageMetadata` — `promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount` (последний кусок);
- `promptFeedback.blockReason` — сразу `blocked_content`.

После конца стрима склеенный текст проходит `JSON.parse` → `postprocess` (§5.5) → `done`.

### 5.3. Повторы

- Один автоповтор через 1 с при сетевой ошибке, `429`, `500` или `503` — **только если клиенту ещё не отправлен ни один `delta`**.
- После первого `delta` повторов нет: клиент получает `error`, а пользователь нажимает «Повторить».
- `429` после повтора → `rate_limited` с `retryAfter: 30`.
- `400` или `403` от Gemini (неверный ключ, недоступная модель) → `upstream_error`, в лог пишется `status` и `error.status` из ответа.

### 5.4. Mock-режим (`_lib/mock.js`)

Включается, если `GEMINI_MODE=mock` или нет `GEMINI_API_KEY`. Отдаёт тот же протокол, что и `live`: шаблонный пост на языке запроса, учитывающий площадку и угол, режется на куски по 3–12 символов с задержкой 20–40 мс. Служебные идеи для ручных проверок:

| `idea` содержит | Поведение |
|---|---|
| `__error__` | `error: upstream_error` после ~200 символов |
| `__blocked__` | `error: blocked_content` до первого `delta` |
| `__slow__` | задержка 500 мс между кусками |
| `__long__` | тело длиннее жёсткого лимита площадки (проверка предупреждений) |

### 5.5. Постобработка (`_lib/postprocess.js` + `core/hashtags.js`)

1. Все строки: `trim`, `\r\n` → `\n`, 3 и больше переводов строки подряд → 2.
2. `title`: убрать обрамляющие кавычки, `**`, ведущие `#`; перевод строки → пробел.
3. `hashtags` (`normalizeHashtags(list, max)`):
   - убрать `#` в начале и все символы, кроме `\p{L}\p{N}_`;
   - пустые отбросить, дубли (без учёта регистра) убрать;
   - добавить `#`, обрезать до `PLATFORMS[p].hashtags.max`.
4. Если `title`, `body` или `cta` пустые → `bad_output`.
5. `warnings = checkLimits(post, platform)` — массив объектов:
   - `{field:'total', level:'hard', limit:2200, actual:2350}` — превышен жёсткий лимит площадки;
   - `{field:'total', level:'soft', limit:1500, actual:1620}` — превышена рекомендованная длина;
   - `{field:'title', level:'hard', limit:100, actual:112}`;
   - `{field:'hashtags', level:'soft', limit:3, actual:1}` — меньше минимума.

   `total` считается по строке `formatForCopy(post, platform)`.

Текст никогда не обрезается автоматически (FR-14). Предупреждения показывает карточка (§9.4).

## 7. Клиент: стриминг и состояние

### 7.1. `api.js` — `streamGenerate(payload, { signal, onDelta, onDone, onError })`

- `fetch('/api/generate', { method:'POST', body, signal })`. `EventSource` не подходит: он умеет только GET.
- Ответ не 200 → читаем JSON и вызываем `onError({code, retryAfter})`.
- Ответ 200 → `response.body.getReader()` + `TextDecoder`, буфер режется по `\n\n`, строки `event:` и `data:` разбираются вручную, комментарии (`:`) пропускаются.
- Если поток закончился без `done` или `error` → `onError({code:'upstream_error'})`.
- `AbortError` → `onError({code:'aborted'})`.

### 7.2. `core/partial-json.js` — `parsePartial(text) → object | null`

Достраивает незаконченный JSON до валидного и разбирает его:
1. Проход по символам: отслеживаются «внутри строки», экранирование и стек `{`/`[`.
2. Если конец внутри строки — отрезать незаконченную escape-последовательность (`\`, `\u` + меньше 4 hex) и закрыть кавычку.
3. Отрезать висящий хвост: `,`, `:`, ключ без значения (`"bo` или `"body":`).
4. Закрыть открытые контейнеры в обратном порядке.
5. `JSON.parse`. При ошибке — вернуть последний успешный результат (хранится снаружи, в карточке).

Пример: `{"title":"Скидка 20%","body":"Только в ноя` → `{title:"Скидка 20%", body:"Только в ноя"}`.

### 7.3. Отрисовка

- Каждый `delta` дописывается в буфер карточки. Отрисовка — не чаще одного раза за кадр (`requestAnimationFrame`): `parsePartial(buffer)` → обновление `textContent` четырёх полей.
- Поле, которое сейчас пишется (последний ключ в разобранном объекте), получает класс `is-typing` — это мигающий курсор.
- По `done` поля заменяются итоговым `post` с сервера: он нормализован и может немного отличаться от потока, например хэштегами.

### 7.4. Карточка: состояния

```
idle ──generate──▶ streaming ──done──▶ done ──regen/tweak──▶ streaming
                      │  └──error──▶ error ──retry──▶ streaming
                      └──stop────▶ aborted ──regen──▶ streaming
```

| Состояние | Кнопки | В историю |
|---|---|---|
| `streaming` | (общая «Остановить» внизу) | — |
| `done` | Копировать, Переписать, быстрые правки | сохраняется при входе в состояние |
| `error` | Повторить (недоступна до `retryAfter`) | — |
| `aborted` | Переписать; частичный текст виден, копирование доступно | — |

### 7.5. Управление генерацией (`ui/variants.js`)

- «Написать 3 варианта» и «Переписать все»: прервать текущие запросы → создать 3 карточки с углами из `ANGLES` → 3 параллельных `streamGenerate`. Все три получают общий `generationId`.
- «Переписать» и быстрые правки на карточке: прервать только её запрос, отправить с `previous` = текущий пост карточки.
- «Остановить» (FR-13): `abort()` у всех карточек в состоянии `streaming`.
- Пока есть хотя бы одна карточка в `streaming`, нижняя кнопка — «Остановить», иначе — «Переписать все» (если бланк свёрнут) или «Написать 3 варианта».
- `rate_limited` в любой карточке: остальные запросы не прерываются, у этой карточки — таймер обратного отсчёта на кнопке «Повторить».

## 8. Хранение (`store.js`)

### 8.1. Ключи `localStorage`

| Ключ | Тип |
|---|---|
| `spg.prefs.v1` | `{ business: string, ideaDraft: string, platform, language, tone }` |
| `spg.history.v1` | `HistoryItem[]`, новые в начале |

```ts
type HistoryItem = {
  id: string;            // crypto.randomUUID()
  generationId: string;  // общий для трёх вариантов одной генерации
  createdAt: string;     // ISO
  platform: 'telegram' | 'instagram' | 'youtube';
  language: 'ru' | 'uz' | 'en';
  tone: string;
  angle: 'benefit' | 'story' | 'engagement';
  idea: string;
  post: { title: string; body: string; cta: string; hashtags: string[] };
  starred: boolean;
};
```

### 8.2. Правила

- Каждое обращение к `localStorage` обёрнуто в `try/catch`. Если хранилище недоступно (приватный режим), приложение работает без истории и показывает один тост «История не сохраняется в этом режиме браузера».
- `prefs` сохраняются с задержкой 500 мс после ввода. `ideaDraft` очищается только кнопкой «×» в поле.
- В историю попадает каждый вариант, дошедший до `done`. Перегенерация создаёт новую запись, старая остаётся.
- Ограничение (FR-45): после вставки, если записей больше 200, удаляются самые старые без звёздочки.
- `QuotaExceededError` → удалить 20 самых старых без звёздочки и повторить один раз. Не помогло — тост «Память браузера заполнена, удалите часть истории».
- Чтение: невалидный JSON или неизвестная версия → начать с пустого списка, испорченное значение сохранить под `spg.history.corrupt` (на случай ручного восстановления).
- Изменения в другой вкладке (событие `storage`) перечитываются в открытом экране «История».

## 9. Интерфейс

### 9.1. Навигация

Роутинг по hash: `#/` — «Создать», `#/history` — «История». В шапке иконка часов ведёт в историю, стрелка «←» — обратно. Кнопка «Назад» в браузере работает естественно.

### 9.2. «Создать» (`ui/form.js`)

- Поля «О бизнесе» и «Идея поста»: `textarea`, автоматическая высота до 8 строк, счётчик `123 / 1500` (становится красным за пределами диапазона). Ошибка — текстом под полем после первой потери фокуса или попытки отправки, `aria-describedby` указывает на ошибку.
- Под идеей — чипы-подсказки: «Акция», «Новинка», «Отзыв клиента», «Полезный совет», «Анонс события». Касание добавляет в поле шаблон («Акция: …») и ставит курсор на место «…».
- Соцсеть — сегментный переключатель (`role="radiogroup"`) из 3 кнопок с иконками (инлайн-SVG).
- Язык и тон — нативные `<select>`: на телефоне открывают системный выбор.
- Нижняя закреплённая панель: «Написать 3 варианта», ширина 100 %, высота 56 px, `padding-bottom: env(safe-area-inset-bottom)`.
- После запуска форма сворачивается в строку-резюме «Instagram · RU · Акция −20%… ✎». Касание по строке разворачивает форму.

### 9.3. Варианты (`ui/variants.js`, `ui/sheet.js`)

- Ширина < 1024 px — карточки друг под другом. От 1024 px — 3 колонки. Контейнер результатов — до 1100 px, форма — до 640 px.
- После запуска экран плавно прокручивается к первой карточке (`scrollIntoView`, без анимации при `prefers-reduced-motion`).
- Карточка сверху вниз:
  - бейдж «Вариант 1 · Выгода»;
  - заголовок (жирный, 18 px);
  - текст (`white-space: pre-wrap`);
  - CTA (выделен фоном);
  - хэштеги (цвет акцента);
  - строка «812 / 1500» и предупреждения;
  - чипы быстрых правок;
  - «Переписать» и «Копировать».
- У каждого поля — маленькая иконка копирования (FR-31): 32 px визуально, зона касания 44 px.
- Пока не пришёл первый символ, по пустому листу проходит растровый «валик» (DESIGN D4); при `prefers-reduced-motion` — статичная растровая заливка.

### 9.4. Предупреждения

| `level` | Вид |
|---|---|
| `soft` | Серый текст: «Длиннее рекомендованного для Instagram (1620 / 1500)» |
| `hard` | Жёлтая плашка с иконкой: «Не поместится в Instagram: 2350 из 2200 символов. Нажмите «Короче».» |

Счётчик символов пересчитывается во время стриминга на клиенте той же функцией `checkLimits`.

### 9.5. «Архив» (`ui/archive.js`)

- Сверху — поиск (`input type="search"`, фильтр по подстроке в `title`, `body`, `cta` и `idea`, без учёта регистра, с задержкой 150 мс) и чипы «Все / Telegram / Instagram / YouTube / ★».

- Удаление сразу убирает пост и показывает тост «Удалено · Отменить» на 5 с.
- «Очистить историю» внизу списка открывает нативный `confirm()`. Отмены после этого нет. Посты со звёздочкой тоже удаляются, и текст подтверждения об этом говорит.
- Список рендерится целиком: 200 элементов — без виртуализации.

### 9.7. Копирование (`clipboard.js`)

1. `navigator.clipboard.writeText(text)`.
2. Если не получилось — скрытая `textarea` + `select()` + `document.execCommand('copy')`.
3. Если не получилось и так — модальное окно с выделенным текстом и подсказкой «Нажмите и удерживайте, чтобы скопировать».

Успех — штамп «Скопировано» на листе (DESIGN D6) и `navigator.vibrate?.(10)`; в архиве — тост «Скопировано» (FR-32).

## 12. Безопасность и приватность

- Ключ Gemini есть только в переменных окружения Vercel и в локальном `.env` (в `.gitignore`).
- Вывод модели вставляется только через `textContent`. Код не использует `innerHTML` с данными. CSP запрещает инлайн-скрипты (§3.2), поэтому весь JS — в файлах.
- Ввод пользователя в промпте обёрнут в теги и помечен как данные (§6.1). Это снижает риск prompt injection, но не устраняет его. Защищаемся тем, что модель не имеет инструментов и доступа к данным: худший исход — странный пост у самого автора запроса.
- `public/privacy.html` (RU): что вводит пользователь; что текст передаётся в Google Gemini API для генерации; что на бесплатном тарифе Google может использовать данные для улучшения своих продуктов; что история хранится только в браузере и удаляется кнопкой «Очистить»; что сервер не хранит тексты; контакт. Ссылка — в подвале экрана «Создать».
